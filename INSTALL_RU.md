# Быстрый старт: новый интерфейс Builder

После обновления ветки откройте `project.godot` в Godot 4.7.2 и запустите приложение. На **Главной** доступны GitHub, репозитории и ИИ. В боковом меню появились **Загрузить из GitHub**, **ИИ-помощник** и **Выйти из Builder**.

## GitHub: три шага

1. **GitHub-аккаунты → Войти через GitHub**. Builder открывает системный терминал с официальной авторизацией GitHub CLI через браузер. Если утилита ещё не установлена, откроется её официальный сайт.
2. После входа нажмите **Проверить подключение**. Builder обнаружит аккаунт без ручного ввода логина. Можно добавлять несколько аккаунтов и переключать их.
3. Нажмите **Загрузить из GitHub**: выберите каталог, найдите репозиторий и нажмите **Добавить проект**. Для приватных репозиториев нужны соответствующие права GitHub.

Клонирование сейчас происходит через `gh repo clone`; очень большие репозитории могут временно приостанавливать интерфейс.

## ИИ без API-ключа

В **ИИ-помощнике** есть выбор источника: **ChatGPT**, **Ollama**, **LM Studio** или **OpenAI API**.

**ChatGPT:** нажмите **Установить вход в ChatGPT**, затем **Продолжить с ChatGPT** и разрешите использование подписки. Для установки официального DevKit нужен Node.js 22.12+ и интернет. Если установка в интерфейсе не сработала, используйте `node bridge/setup.mjs`.

**Ollama:** установите Ollama с https://ollama.com/download, скачайте локальную модель (например, командой `ollama pull qwen2.5-coder:1.5b`) и нажмите **Найти модели**.

**LM Studio:** установите LM Studio с https://lmstudio.ai/, загрузите локальную модель, включите API-сервер (127.0.0.1:1234) и нажмите **Найти модели**.

**OpenAI API:** дополнительный режим с отдельным ключом и оплатой API.

Builder обращается к локальным серверам на 127.0.0.1:11434 (Ollama) или 127.0.0.1:1234 (LM Studio). Чтобы данные оставались на вашем компьютере, выбирайте локально установленные модели, а не облачные варианты сервиса.

## Выход

**Выйти из Builder** закрывает приложение. **Отключить** в разделе GitHub-аккаунтов отключает выбранную авторизацию GitHub CLI после подтверждения. **Отключить аккаунт** в ChatGPT завершает его сессию в Builder.

# Установка Builder и вход через ChatGPT без API-ключа

Builder — локальное приложение Godot 4 с GitHub и встроенной перепиской с ИИ.

## Подготовка

Нужны: **Godot 4.2+**, **Node.js 22.12+**, **npm**, **Git**. Для хранения учётных данных потребуется работающая система защищённых секретов: Keychain (macOS), Credential Manager (Windows) или Secret Service / kernel keyutils (Linux).

Откройте каталог Builder в терминале и **один раз** выполните:

```sh
node bridge/setup.mjs
```

Команда клонирует закреплённую версию **официального OpenAI Sign in with ChatGPT DevKit**, соберёт его Node SDK и установит компонент безопасного хранения ключа в операционной системе.

Затем откройте `project.godot` в Godot и запустите его клавишей **F5**. Если окно Godot не видит Node.js, укажите абсолютный путь к исполняемому файлу в **Настройки → Node.js для ChatGPT**.

## Вход в аккаунт ChatGPT

1. Перейдите в раздел **ChatGPT · в Builder**.
2. Нажмите **Продолжить с ChatGPT**. Откроется официальный сайт авторизации OpenAI в обычном браузере.
3. Войдите в свой ChatGPT-аккаунт, выберите рабочее пространство и **разрешите использование подписки** в Builder.
4. Дождитесь загрузки списка доступных моделей и выберите одну из них.
5. Напишите сообщение. При желании прикрепите исходный файл из выбранного проекта. Только явно добавленный файл отправляется в OpenAI.
6. Для завершения связи используйте **Отключить аккаунт**. Для очистки локальной переписки — **Новый чат**.

Для запросов без API-ключа требуется подходящая подписка **ChatGPT Plus или Pro**, а также согласие на использование плановых лимитов и доступность функции для выбранного аккаунта. Вход без разрешения использовать подписку не даёт возможности отправлять запросы. Доступ к истории чатов chatgpt.com **не предоставляется**.

При необходимости включите отдельный флажок **Вместо подписки использовать OpenAI API-ключ** — это необязательный прежний режим с отдельным биллингом.

## Безопасность

В Builder не вводятся пароль или cookies ChatGPT. OAuth проходит в системном браузере, официальный SDK проверяет ответ; токены не передаются интерфейсу Godot и не записываются в GitHub. Они локально шифруются ключом, хранящимся в системном менеджере учётных данных. Bridge принимает запросы **только на 127.0.0.1** и требует непредсказуемый локальный секрет.

Репозиторий должен распространяться с подходящей лицензией открытого исходного кода для использования пути open-source интеграции. **Официальный DevKit имеет отдельную некоммерческую лицензию**. Его исходники в Builder не копируются — устанавливаются при настройке.

## Полный экран

**F11** или кнопка в правом верхнем углу: переключение оконного и полноэкранного режимов.

## Диагностика

Если при входе написано **«Не установлен официальный DevKit»**, повторите `node bridge/setup.mjs` в каталоге проекта. Если **«Не удалось запустить Node.js»** — проверьте установленную версию и путь к `node`. Если учётная запись подключена, но модели не появляются — проверьте разрешение использовать подписку и страницу [Управление использованием ChatGPT](https://chatgpt.com/settings/usage).

Ветка `feature/godot-workspace-mvp` — MVP. Проверка настоящего OAuth-входа требует участия пользователя в браузере и запусков на нужной ОС; релиз пока не считается протестированным.


## Godot 4.7.2: исправления Unicode и UID

В этой ветке исправлена проверка бинарного файла: вместо проблемного экранированного нулевого символа теперь проверяются **байты** через `PackedByteArray.has(0)`. Все шесть файлов `scripts/*.gd.uid`, автоматически сгенерированных Godot 4.7.2, включены в Git. Каталоги скачанного SDK и Node.js модулей исключены из сканирования редактором с помощью `.gdignore`.

Если у вас была старая сборка проекта, скачайте **обновлённую ветку** `feature/godot-workspace-mvp` (не старый ZIP и не `main`), закройте Godot и откройте проект снова. Для проверки можно выполнить:

```sh
git fetch origin
git switch feature/godot-workspace-mvp
git pull --ff-only origin feature/godot-workspace-mvp
node bridge/setup.mjs
```

Если предупреждение `Missing .uid file` сохранилось из **старого кэша**, полностью закройте Godot, удалите только автоматически генерируемый каталог `.godot/` в **корне проекта** и снова откройте `project.godot`. Не удаляйте `scripts/*.gd.uid`: это отслеживаемые исходные идентификаторы.

В GitHub Actions включена проверка Godot **4.7.2**, которая теперь считает `Unicode parsing error` и отсутствие отслеживаемых `.gd.uid` ошибкой CI.


## Полноэкранный режим в Godot 4.7.2

В редакторе Godot **встроенный режим Game** не поддерживает полноэкранные окна. Теперь Builder определяет его через `Engine.is_embedded_in_editor()` и при нажатии кнопки показывает пояснение вместо ложного переключения. Если запустить Builder в отдельном окне, кнопка и **F11** переключают режим через нативный `DisplayServer`. При выходе из полного экрана восстанавливаются прежние размеры и расположение окна.

Чтобы использовать полноэкранный режим при разработке:

1. Откройте в редакторе Godot вкладку **Game**.
2. Нажмите меню **⋯** в панели Game.
3. Снимите флажок **Embed Game on Next Play**.
4. Остановите проект и снова нажмите **F5**; приложение запустится в отдельном окне.
5. Нажмите **На весь экран** либо **F11**.

Режим **Make Game Workspace Floating on Next Play** не равнозначен отключению встраивания: при включённом Embed Game изменение полноэкранного режима по-прежнему может не работать.

Документация движка: https://docs.godotengine.org/en/4.7/tutorials/editor/game_embedding.html
